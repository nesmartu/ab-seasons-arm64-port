# Инструкция по сборке

[English](BUILD_EN.md) · [Описание](README_RU.md)

Команды выполняются из `ab-seasons-arm64-port/`. Поддерживаемая система сборки — Linux x86_64. Нужно примерно 12 ГБ диска и 8 ГБ памяти; при нехватке памяти используйте `--jobs 1` или `--jobs 2`. Установите Python 3.11+ с venv/pip, Java 17, сертификаты CA и unzip. Android Studio, Gradle, apktool и компиляция Java не требуются.

```bash
sudo apt-get update
sudo apt-get install -y python3 python3-venv python3-pip openjdk-17-jdk-headless ca-certificates unzip
python3 -m venv ../seasons-venv
source ../seasons-venv/bin/activate
python -m pip install -r requirements.txt
python tools/setup_toolchain.py --tools ../toolchains
# Скопируйте оригинальный APK Seasons 6.6.2 в input/.
python tools/release.py --tools ../toolchains --jobs 4
```

Подготовка скачивает NDK r27d и Build Tools 36.0.0 с проверкой контрольных сумм и устанавливает CMake 3.30.5/Ninja 1.11.1.1 из включённых wheels. Эти хеши проверяют инструменты, а не входные APK. При подготовке нужен интернет; далее можно собирать без сети. Исходники и лицензии зависимостей находятся в `third_party/`.

Без `--apk` обрабатываются все файлы непосредственно в `input/*.apk`; имя не обязано совпадать с примером. Выбор одного файла или другой конфигурации:

```bash
python tools/release.py --tools ../toolchains --apk /path/to/game.apk
python tools/release.py --tools ../toolchains --config configs/original.toml
```

Команда release проверяет совместимость, применяет фиксы в `build/prepared/<имя-результата>/<имя-входа>.apk`, проверяет промежуточный ARM32 APK, компилирует вспомогательный runtime и ARM64-мост, подписывает и выравнивает порт и проверяет сохранность данных. Ошибка фикса останавливает сборку. Оригинальный вход не перезаписывается. Для полной цепочки используйте `tools/release.py`; низкоуровневые `tools/build.py` и `tools/package_apk.py` сами фиксы не применяют.

Результаты: `dist/<имя-входа><набор-фиксов>-arm64.apk` и соответствующая `.bridge.so`. Отчёты: `reports/<имя-входа><набор-фиксов>/`, общий индекс `reports/batch.json`. Набор фиксов входит в имя результата; изменение только пакета или рендера может перезаписать результат того же набора. См. [параметры](docs/SETTINGS_RU.md).

После полной сборки `--package-only` повторно использует мост лишь при совпадении байтов входного движка и объявлений JNI. В архиве нет готового моста порта. При отсутствии моста или несовпадении движка/JNI нужна полная сборка. При переносе каталога с кэшем CMake сначала удалите `build/`.

В Windows используйте Ubuntu x86_64 в WSL2: распакуйте проект в файловую систему Linux и выполните команды Linux. В macOS используйте Linux x86_64 в виртуальной машине либо Docker с `--platform linux/amd64`; на Apple Silicon нужна эмуляция. Нативные PowerShell/macOS/Termux и Linux ARM64 не поддерживаются закреплёнными инструментами. Альтернативные системы отдельно здесь не проверялись.

[Отдельному патчеру](SelectableFixes/README_RU.md) нужны только Python и cryptography. [Эксперимент 4.1.1](4.1.1/README_RU.md) использует собственные вход, конфиг и мост, но общие зависимости и инструменты; фиксы 6.6.2 не применяются.

После изменений выполните [проверки](docs/VERIFICATION_RU.md). Создание чистого ZIP с исходниками:

```bash
python tools/make_source_archive.py ../ab-seasons-arm64-port-sources.zip
```

Архив должен находиться вне дерева исходников. APK, генерируемые отчёты, кэши build/dist, мосты со встроенными игровыми движками и генерируемые бинарные данные движка исключаются. Описания input, вспомогательный runtime, публичные ключи разработки, зависимости и wheels остаются. `SOURCE_FILES.sha256` содержит хеши всех файлов архива, кроме самого списка. Не назначайте всему проекту новую лицензию без выяснения лицензионного происхождения моста; уведомления компонентов сохраняются.
