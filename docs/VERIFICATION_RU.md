# Автоматические проверки

[English](VERIFICATION_EN.md)

После установки зависимостей запустите из корня репозитория:

```bash
python -m unittest discover -s tests -v
python -m unittest discover -s 4.1.1/tests -v
SEASONS_TEST_APK="$PWD/input/game.apk" python -m unittest discover -s SelectableFixes/tests -v
python tools/release.py --tools ../toolchains --jobs 4
```

В `SEASONS_TEST_APK` укажите настоящее имя оригинального входа 6.6.2. Тесты конфигурации используют небольшие образцы манифеста и не требуют полного APK. Тесты поведения выполняют исходный и изменённый Lua с подставными службами: 64 комбинации флагов, повторное применение, порядок добавления, сохранность посторонних ресурсов, 25 уровней Ragnahog и три полученных/неполученных яйца, условия звёзд/перьев, однократные монеты, интерфейсы квестов, 108 предметов косметики и 21 сценарий календаря/старта.

В release выполняются отдельные аудиты патча и порта. Проверяются CRC/пути ZIP, сохранность исходных DEX/ресурсов/движка на этапе патча, выбранные правки Lua/JSON, ARM64 ELF/встроенный движок/JNI/импорты/релокации, выравнивание ELF на 16 КиБ, названия/значки/пакет/параметры, подписи и выравнивание ZIP.

Проверка повторяемости в двух чистых каталогах требует заполненного `input/`:

```bash
python tools/check_reproducible.py --tools ../toolchains --jobs 4
```

`--package-only` проверяет лишь повторную упаковку с уже собранным подходящим мостом и не подтверждает компиляцию. Отдельные сборки и аудит каждого флага: `python SelectableFixes/check_builds.py --input input/game.apk`. `--matrix` отдельного патчера создаёт пять сочетаний, а его `check_reproducible.py` сравнивает их с чистой повторной сборкой.

Генерируемые журналы и аудиты находятся в игнорируемых `reports/`, а не в истории выпусков исходников. Краткий снимок проверки в этой папке описывает фактически выполненные проверки этого комплекта. Запуск на устройстве вынесен в отдельный [план](DEVICE_TESTING_RU.md).
